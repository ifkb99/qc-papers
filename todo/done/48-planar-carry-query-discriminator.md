# Turn the planar existence result into a useful arithmetic discriminator

Completed at bounded construction and exact-query scope. C87 gives an
explicit permutation family, a grid minor surviving the all-bit query's
endpoint deletions, and a nonzero direct weighted-dimer formula. DM owns
the independent checks and retained verifier defects. The strongest
identified baseline removes the generic local gadgets and has fixed
global sign. This is progress toward a concrete discriminator, not a
practical memory advantage or exclusion of all simpler formulas. TODO49
owns that remaining reduction audit and the conditional next comparison.
No performance pilot was justified or run. The original brief follows.

C86/MG provide a proved, exact implementation of known matchgate/FKT
machinery for two independent-operand additions linked by a planar bit
permutation. They also establish that this architecture permits unbounded
treewidth. Neither fact proves a hard scalar instance or a useful simulation
improvement. Do not repeat tiny correctness fixtures or run a wide Pfaffian
pilot simply to demonstrate the known planar algorithm.

First extract an explicit growing family of actual permutations from the
published Eppstein construction and the audited cleanup, or another verified
construction. Work algebraically and with a few bounded adjacency fixtures.
Check that the resulting graph really has two carry paths and one perfect
matching, and that the actual arithmetic circuit realizes this permutation.
Use a constructive minor or other rigorous width certificate where possible;
a heuristic elimination width is only an upper bound. Bit reversal alone
has a cheap carry ordering and is not a sufficient family.

Specify a deterministic family of mask tuples for the exact C86 normalized
signed scalar, retaining the same initial-carry convention and output.
Before benchmarking, derive whether the query uses the purported growing
interaction. Apply constant-character simplification, cyclic-convolution
highest-bit zero tests, ignored-pivot cancellation and query-specific factor
pruning. Nonzero alone is insufficient: a single carry coefficient or an
efficient closed formula would explain the result. Generic architecture
width cannot lower-bound this weighted scalar. Preserve any proposed family
that collapses as a recorded negative result.

Compare the best inexpensive arithmetic formula, symbolic cancellation,
bit-position contraction, an improved tensor elimination order and the
known planar Pfaffian route on the same supplied inputs and exact outputs.
Explicit weighted-automaton construction/minimization is another baseline;
charge discovering the representation. Wallén's parallel concatenation
result does not settle arbitrary serial composition. Signed trail sums
cannot be replaced by best-trail weights, squared correlations or magnitudes.
If a phase-aware stabilizer representation is competitive for the selected
task, include its regrouping/setup costs too.

Only if this audit leaves a meaningful opportunity, register one extra
prediction about total time and peak allocated memory for a bounded matched
comparison. Fix the family construction and query rule, then vary only its
one growth parameter. Charge permutation and graph generation, planarity,
matching/orientation, exact integer sizes, retained input/circuit storage,
temporary matrices and final sign/normalization. A dense-vector-only win or
an O(w^2) count of rational entries is not a byte comparison. Polynomial
memory alone is already available through exponential-time enumeration.

Known matchgate tractability is not a novelty claim. State separately whether
the exact arithmetic application has prior art and whether this project has
found a useful algorithmic improvement. If all promising scalar families
collapse, record that and redirect without treating one failed family as a
general impossibility result. General CNOT interfaces or actual shared-
scratch modular additions are separate possible extensions: their local
parity and arity-four matchgate identities must be audited before carrying
over C86, and their clean/full-space maps must remain distinct.

Use the authorized board swarm, with one canonical writer and independent
proof/source/evidence review. Core first for scientific execution; keep all
runs bounded under TODO34. Predictions precede execution, controls must
exercise sign cancellation and a wrong structural assumption, and failed
scripts/logs remain intact. TODO42's sampling-cost question stays separate.
